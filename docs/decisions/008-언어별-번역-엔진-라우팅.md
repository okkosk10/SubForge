# ADR 008: 언어별 번역 엔진 라우팅

## 상태
Accepted

## 결정
- SubForge는 언어별로 번역 엔진 라우팅을 다르게 적용한다.
- `ja -> ko`는 AIHub direct 모델(`sappho192/aihub-ja-ko-translator`)을 우선 사용한다.
- AIHub 실패 시 Argos fallback(`ja -> en -> ko`)을 사용한다.
- `en/ru/zh -> ko`는 Argos 경로를 유지한다.

## 배경
- 단일 Argos 경로만 사용할 때 일본어 번역 품질 저하 사례가 반복되었다.
- AIHub direct 모델은 일본어 문장에서 더 자연스러운 한국어 결과를 제공했다.

## 근거
- AIHub direct 샘플: `明日は雨が降るかもしれません。 -> 내일은 비가 올지도 몰라요.`
- Argos pivot 샘플: `明日は雨が降るかもしれません。 -> 그것은 내일 비일지도 모릅니다.`

## 관측성
- Worker 응답은 optional metadata를 포함한다.
  - `provider`
  - `fallbackUsed`
  - `fallbackReason`
  - `timing`
- Pipeline 이벤트로 provider/fallback/timing을 기록한다.

## 트레이드오프
- 장점: 일본어 품질 개선
- 단점: one-shot Worker 구조에서 요청마다 AIHub 모델 로드 비용이 발생

## 후속 과제
- persistent worker 전환 시 로드 비용 절감 가능성 검토
- 언어별 모델 품질/속도 재평가
